# AUREX Model Card

## 1. Model collection

**Project:** AUREX – AI-Powered Music Genre and Mood Classification  
**Model format:** ONNX  
**Inference environment:** Browser, using ONNX Runtime Web  
**Model asset location referenced by the application:**  
https://github.com/shockboyyy/aurex-models

This model card documents how AUREX uses the pretrained model assets. It does not claim that the AUREX team trained the underlying models.

## 2. Intended use

The models are used to provide exploratory music-style and mood analysis for a user-selected audio track. The outputs are displayed as information to support music discovery and DJ-oriented interpretation.

The system is not intended for high-stakes decisions, psychological assessment, commercial rights decisions, or definitive music categorisation.

## 3. Model components

### 3.1 Genre / music-style model

- Asset referenced by the application: `discogs-effnet-bsdynamic-1.onnx`
- Metadata file: `discogs-effnet-bsdynamic-1.json`
- Expected metadata: 400 class labels.
- Output used by AUREX: style scores and a 1,280-dimensional embedding.
- The embedding is also passed to the mood models.

### 3.2 Mood models

AUREX loads five separate ONNX mood models:

| Model | Output represented in AUREX |
|---|---|
| `mood_happy-discogs-effnet-1.onnx` | Happy |
| `mood_sad-discogs-effnet-1.onnx` | Sad |
| `mood_aggressive-discogs-effnet-1.onnx` | Aggressive |
| `mood_relaxed-discogs-effnet-1.onnx` | Relaxed |
| `mood_party-discogs-effnet-1.onnx` | Party |

Each model receives the 1,280-value embedding produced by the genre model. AUREX reads the positive-class score defined for each mood model.

The five mood values are independent outputs. They are not a softmax distribution and are not expected to sum to 1.

## 4. Input processing in AUREX

The application performs the following processing before inference:

- Decodes the uploaded audio using the browser audio engine.
- Converts the audio to mono.
- Resamples it to 16,000 Hz.
- Uses Essentia.js `TensorflowInputMusiCNN` to compute 96-band Mel features.
- Uses 512-sample frames and a 256-sample hop.
- Groups features into patches of 128 frames with a patch hop of 62 frames.

These are application preprocessing settings. They should not be confused with claims about the original models' complete training pipeline.

## 5. Output and post-processing

The application runs inference for each audio patch, accumulates genre and mood outputs, and calculates track-level results for display.

The dashboard presents:
- Ranked genre/style predictions.
- Five mood scores.
- A mood radar chart.
- A mood timeline based on patch-level mood outputs.
- A DJ Track Character description.

The DJ Track Character description is generated by application rules using classification results. It is not an additional neural network prediction.

No formal accuracy, precision, recall, F1-score or benchmark result should be claimed unless the team conducts a separate evaluation using labelled test data and reports the methodology.

Manual examples are useful functional checks, but they do not establish model accuracy or generalisation.

## 8. Limitations and risks

- Genre and mood are subjective and may vary between listeners.
- A model may assign high scores to multiple styles or moods.
- The model's supported labels limit the categories AUREX can predict.
- Predictions can be affected by audio quality, production style, track structure and domain differences.
- Mood scores should not be interpreted as calibrated probabilities without calibration evidence.
- Model outputs should be treated as suggestions, not definitive descriptions.
- Performance depends on browser, device and network conditions for model downloads.
